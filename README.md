# وحدة تقنية المعلومات — الحزمة الكاملة V26

بُنيت هذه الحزمة على V24 المرسلة، وتأكد تطابق صفحة V24 مع صفحة المستودع الحالي عند المراجعة. أضيفت إصلاحات الحسابات والمنفذين وخدمة إشعارات الخلفية. جميع ملفات الموقع موجودة في الجذر، بما فيها الصور والأيقونات وملفات التثبيت.

المستودع المقصود: https://github.com/anasmonti80-png/CTE-Jeddah-IT-Support

رابط التطبيق: https://anasmonti80-png.github.io/CTE-Jeddah-IT-Support/

## ابدأ هنا

1. فك ضغط الحزمة. لا تشغّل الملفات من داخل ZIP.
2. لتشغيل إشعارات الخلفية، شغّل `START-PUSH.cmd` مرة واحدة واتبع [دليل الإشعارات](NOTIFICATIONS_GUIDE.md). هذا يحدّث `push-config.js` محليًا بعد نجاح النشر.
3. ارفع محتويات الحزمة المفكوكة إلى جذر المستودع الحالي. يجب أن يظهر `index.html` مباشرة بجانب `manifest.json` و`sw.js`، وليس داخل مجلد إضافي. ارفع الملفات المفكوكة، وليس ملف ZIP.
4. في Settings → Pages اختر النشر من الفرع `main` والمجلد `/(root)`، إن لم يكن مضبوطًا بالفعل. انتظر اكتمال النشر في Actions، ثم افتح رابط التطبيق وأعد تحميله.
5. من حساب المدير افتح «تفعيل الإشعارات» أعلى الصفحة، ثم «إعداد Web Push» واحفظ Public VAPID Key الموجود في Firebase. لا يُطلب إدخاله لكل مستخدم.
6. فعّل الإشعارات مرة واحدة على كل جهاز. اختبر بزر «اختبار على هذا الجهاز» بعد ظهور جاهزية خدمة الإرسال.

يمكنك استبدال ملفات الموقع القديمة بهذه الحزمة كاملة. البلاغات والحسابات محفوظة في مشروع Firebase الحالي؛ الحزمة لا تحتوي أمرًا لحذفها أو إعادة ضبطها. لم تُحذف ملفات المستودع ولم تُرفع هذه النسخة تلقائيًا.

إذا شغّلت أمر الإعداد ثم أردت رفع الحزمة كاملة: استثنِ `cloudflare-push/node_modules` و`.wrangler` وأي ملف مفاتيح خاص. ملفات المصدر المرفقة نفسها لا تحتوي مفتاح حساب الخدمة. ملف `.gitignore` لا يحمي من السحب اليدوي لملف سري في صفحة GitHub، لذلك احتفظ بملف المفتاح خارج الحزمة دائمًا.

## الملفات الموجودة

| الملف | وظيفته |
|---|---|
| `index.html` | التطبيق والبلاغات والتقارير القابلة للتعديل |
| `manifest.json` | اسم التطبيق وأيقوناته وتثبيته |
| `sw.js` | تشغيل التطبيق ومعالجة إشعارات الخلفية ومنع التكرار المعتاد |
| `push-client.js` | تفعيل الجهاز وحفظ الربط وتجديده |
| `push-config.js` | رابط التطبيق وخدمة الإرسال؛ يحدّثه أمر الإعداد |
| ملفات PNG وJPG | الصور والأيقونات اللازمة |
| `START-PUSH.cmd` | الإعداد على Windows بنقرتين |
| `SETUP-PUSH.ps1` | البديل في PowerShell |
| `setup.sh` | البديل على macOS/Linux: `sh setup.sh` |
| `cloudflare-push/worker.mjs` | كود خدمة الإرسال الآمنة |
| `cloudflare-push/setup.mjs` | إعداد الخدمة وربط مفتاح Firebase |
| `cloudflare-push/wrangler.json` | إعداد Cloudflare والجدولة |
| `cloudflare-push/schema.sql` | سجل الإرسال ومنع التكرار وإعادة المحاولة |
| `cloudflare-push/package.json` و`package-lock.json` | أدوات الإعداد وإصداراتها المثبتة |
| `cloudflare-push/test/` | اختبارات الخدمة والإعداد |
| `VALIDATION.json` | نتيجة الاختبارات وحدود التحقق |

لا يلزم `index.js` قديم في جذر الموقع. الكود البديل لخدمة الإرسال موجود كاملًا في `cloudflare-push/worker.mjs`، ويستدعيه الإعداد تلقائيًا. لا تنسخ ملف خادم قديم فوق ملفات الحزمة.

## التعديلات المحفوظة

- تصميم تقريري البلاغ عالي الخطورة والفترة، والصور المرجعية، والنصوص والأرقام القابلة للتعديل.
- مؤشرات قابلة للإضافة والحذف، وأعمال مستخرجة من سجلات الفترة قابلة للتعديل، حتى ست بطاقات.
- تأكيد إعادة فتح البلاغ برقم البلاغ، وحفظ النسخة السابقة وهوية من عدّلها، مع الحفاظ على الإنجاز حتى حفظ التعديل.
- الاسم الظاهر منفصل عن اسم الدخول، ومبنيا الإدارة والصيانة، واختيار عدة منفذين من حسابات IT وIT Manager.
- زر إغلاق التقرير، وإشعارات وتثبيت أعلى الصفحة، وإتاحة جرس الإشعارات لجميع الحسابات مع تصفية إشعارات كل حساب.
- استلام واحد عند تزامن الضغط، وانتقال واحد للمراجعة عند تشغيل النظام على عدة أجهزة.

## ما تم التحقق منه

نجحت اختبارات البلاغات والتقارير والإشعارات والخادم والإعداد، واختبار الصفحة الكاملة في Edge مع مكتبة Bootstrap الفعلية وبديل اختباري لـ Firebase. جرى تشغيل Worker وقاعدة D1 محليًا في Miniflare. لم يتصل اختبار الواجهة ببيانات المستخدمين الحقيقية.

هذه حزمة تم اختبارها محليًا. تشغيل إشعارات هذه النسخة على الهاتف يحتاج نشر الخادم المطابق لها ثم السماح على الجهاز. رفع HTML وحده لا يشغّل الإرسال الخلفي. لا يزال الإرسال الفعلي إلى هاتف غير مختبر في هذه المراجعة.
